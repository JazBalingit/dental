Fixed this round

Done & verified — 7

H1

Settings password-reset now throttled and attempt-capped

Fixed

app/Http/Controllers/SettingsController.php + app/Http/Controllers/Concerns/ManagesOtp.php

The in-app reset had no rate limit and no lockout — a brute-force path to full account takeover. It now has a 5-per-15-minute limiter, a 5-wrong-guess cap that wipes the code, and the 60-second resend gap.

VerifiedAttempt cap and cooldown exercised via the signup and staff flows that share the same trait.

H2

Double booking closed with row locking

Fixed

app/Http/Controllers/Concerns/BuildsBookingCalendar.php — reserveSlotBlock()

Each schedule row is now read SELECT … FOR UPDATE inside the booking transaction, so two simultaneous bookings for one slot serialise — the second sees "Not Available" and is rejected. First-time row creation is covered by the existing unique index.

VerifiedLive booking reserved the right slots; a second attempt on the held slot was rejected; a free slot still booked.

H3

Authorization moved onto the routes

Fixed

routes/web.php + app/Http/Middleware/{EnsureAdmin,EnsureSuperAdmin,EnsureAuthenticated}.php

The 13 copied guard() methods and ~60 call sites are gone. Access is three middleware applied per route group: auth.session, admin, and admin + superadmin. A route can no longer exist without a gate. The AJAX endpoint returns JSON 401 instead of an HTML redirect. Controllers keep only their data-scoped checks (ownership, profile completeness).

VerifiedEvery page still loads for the right role; logged-out and patient sessions are redirected off admin routes; staff are blocked from the two super-admin pages; EnsureStaffIsVerified still fires first.

M1

Odontogram stored-XSS closed

Fixed

resources/views/partials/odontogram.blade.php

{!! $seed->toJson() !!} → the Blade @json() directive, which hex-escapes < > & ' ". A tooth description can't break out of the <script> block any more.

VerifiedCharted a tooth with </script><img onerror=…> as its description, viewed it on the patient page — rendered as inert text, no <img> injected, JSON.parse still recovers the literal string.

M4

Patients can see their own records

Fixed

GET /my-records → PatientRecordsController::mine() + resources/views/users/my-records.blade.php

New read-only "My Dental Records" page — every completed visit with its odontogram and the dentist's notes, pinned to the caller's own PatientID. Linked from the patient nav on every page. A staff/super-admin hitting it is redirected to the management screen.

VerifiedEmpty state and a populated visit (chart + notes) both render for a patient; super admin is redirected.

M5

Password policy is real now

Fixed

app/Providers/AppServiceProvider.php — Password::defaults()

Every password field (8 of them: signup, staff create, staff change, all reset flows) requires min 8 + upper & lower case + a digit + a symbol.

VerifiedRejected at signup and on the logged-in Settings change with the specific "needs a symbol / number / mixed case" messages; a compliant password passed and actually changed the stored hash.

M6

OTP codes expire in 5 minutes + 60-second resend gap

Fixed

app/Http/Controllers/Concerns/ManagesOtp.php (used by signup, forgot-password, Settings reset, staff verify)

Each code carries an expires_at (5 min) checked before the match, and a sent_at that blocks a resend for 60 seconds. Codes are compared with hash_equals().

VerifiedCompleted a real signup with an in-window code; an immediate resend returned "Please wait 44 seconds" and sent no second email.

Still open

These were in the first review and are not regressions — none were in scope for this round. No high-priority items remain.

Medium — 5

M2

Appointment expiry runs writes on GET page loads

Open

app/Services/AppointmentExpiryService.php — called from calendarData() and several index() actions

Opening the landing / walk-in / approvals / appointments page still silently declines stale appointments, releases slots, writes notifications and sends email. A GET should be safe to repeat. Move it to a scheduled command (schedule:run / cron).

M3

No audit record of who viewed a patient file

Open

PatientRecordsController::index()/mine(), WalkInController::searchPatient()

Edits and archives are logged; opening a chart or running the PII search isn't. Standard expectation for medical records. Add a View / Search activity entry.

M7

Uploaded photos land in the public web root

Open

ProfileController::update(), StaffAccountController::store()/update()

Validation blocks the obvious payloads, but user files shouldn't sit in a served, executable path. Move to storage/app/public (or private + a controller); derive the extension from the validated MIME type.

M8

Debug mode on / production hardening not done

Deploy

.env

APP_DEBUG=true, APP_ENV=local. Fine on your machine; before this is reachable by anyone else: APP_DEBUG=false, APP_ENV=production, config:cache.

M9

Session cookie / transport not hardened

Deploy

config/session.php, no HTTPS enforcement

SESSION_SECURE_COOKIE=true, SESSION_ENCRYPT=true, force HTTPS, and add CSP / X-Frame-Options / X-Content-Type-Options for production.

Low / polish — 8

  • L2 — slot-release logic is still copy-pasted across ~5 files; extract a SlotReservation service.
  • L3 — no automated tests (only framework stubs). The flows verified by hand this round — booking conflict, the approval state machine, the guards, the OTP caps — are exactly what feature tests should lock down.
  • L4 — expireStalePending() loads every Pending row into PHP then filters; push the date comparison into SQL.

  • L8 — 200+ unread admin notifications with no "mark all read"; minor UX drag on the notification menu.

Best-practice standing

For an online appointment + records system, the load-bearing pieces are now in place: authentication gates on the routes, transaction + lock on the booking write, ownership checks on patient-facing endpoints, expiring one-time codes, a real password policy, an activity trail with actor and IP, soft deletes on clinical data, and a patient's right to read their own record.

The gap between here and "production-grade for health data" is now mostly operational rather than structural: move the two remaining behaviours off GET requests (M2), log record access (M3), get uploads out of the web root (M7), and do the deploy-time hardening (M8/M9). Adding a test suite (L3) is what will keep all of the above from quietly regressing.
